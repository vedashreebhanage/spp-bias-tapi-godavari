## 2. Critical history — why this is a rebuild

An earlier AI-generated implementation produced results that **must not be used**.
Its code and outputs are preserved in `archive/ai_v1/`. The audit found:

1. **No basin mask.** Metrics were computed over a rectangular bounding box
   (~165,000 km²) instead of the Tapi polygon (65,145 km²). The shapefile was
   downloaded but never used. ~60% of every reported statistic came from outside
   the basin.
2. **"Terrain stratification" was longitude slicing** (two hardcoded thresholds,
   no elevation data). The paper's central claim was never actually tested.
3. **Extreme rainfall silently deleted** — IMD reader set values >500 mm/day to
   NaN. Five of nine years contain days above 500 mm (max 979.1 mm, 2022).
4. **Sample size overstated** — N reported as ~880,000 day-cells with no account
   of spatial/temporal autocorrelation, from ~90 real grid cells.
5. **DPBA ill-defined** — computed as signed `PBIAS_event − PBIAS_control`, so a
   bias that *improved* during a flood registered as "amplification."
6. **Stage 1 code never existed** — results came from an ephemeral session; only
   Stage 2 scripts were committed. Numbers were unreproducible.
7. **Only CHIRPS, only Tapi** — despite README claims of 3 products × 2 basins.

The arithmetic was internally consistent; it was consistently computing the wrong
thing. **This is the failure mode the rebuild exists to prevent: every step must
produce a visible check (map, count, unit test) before the next step builds on it.**

## 5. Traps already hit — do not repeat

- **The shapefile contains 14 basins, not one.** Their union spans 10–28 °N.
  The Tapi is `HYBAS_ID 4050031520` (PFAF_ID 45404, SUB_AREA 64,337.5 km²).
  `build_mask.py` selects by ID and validates area; never dissolve all records.
- **Scripts must be run from the project root**, never from inside `scripts/`.
  All paths are relative. Running from `scripts/` silently created a phantom
  `scripts/data/raw/era5/` that swallowed a whole ERA5 download.
- **ERA5 daily statistics product rejects accumulated variables.** Solution:
  request `reanalysis-era5-land` with `time=["00:00"]` only — that value is the
  complete total for the *previous* day. Never sum hourly ERA5 values; they are
  cumulative within the day and summing inflates totals several-fold.
- **IMERG OPeNDAP URLs** embed slashes/colons in the query string; naive filename
  derivation collapses all granules onto one file. Filenames are extracted by
  regex on the granule ID.
- **IMD `.GRD` files carry no metadata** — shape `(n_days, 129, 135)` float32 is
  asserted by the reader, validated by byte count.
- **Placeholder dates outlive the intention to fix them.** The `UNVERIFIED` flood
  windows sat in `basins.py` looking authoritative; the 2021 one (Aug 1–20) turned
  out to be almost entirely dry, with only its last three days wet. Anything
  provisional must either fail loudly or be derived — `basins.load_episodes()` now
  raises rather than returning a default.
- Windows: a new PowerShell starts in `system32`; `setx` needs a full VS Code
  restart; Notepad appends `.txt` unless "All Files" is selected.

## 6. Methodology decisions already made

- **Masking:** cell-center-in-polygon on the IMD 0.25° grid.
- **Common grid:** everything aggregated *up* to IMD 0.25° (CHIRPS 5×5 block mean;
  ERA5/IMERG area-weighted). IMD never moves — it is the reference.
- **Terrain:** mean elevation and ruggedness (std) per cell from SRTM 90 m; zones
  as **terciles** of in-basin elevation, not hand-picked thresholds. Bias should be
  analysed as a *continuous* function of elevation (regression with bootstrap CIs),
  with three zones kept only as a descriptive summary.
- **Uncertainty:** block bootstrap over contiguous time blocks and spatial
  clusters. Report grid-cell counts alongside day-cell N.
- **Metrics:** PBIAS, CC, RMSE, KGE, POD/FAR/CSI (1 mm/day), plus P95/P99 quantile
  bias (arguably the most relevant for a flood study).
- **Dry days are kept.** They are signal, not noise — FAR is uncomputable without
  them. Seasonal stratification (JJAS/ON/DJF/MAM) handles the concern properly.
- **Event metric:** redefine on bias *magnitude* (`|PBIAS_episode| − |PBIAS_control|`)
  with significance testing. Both the episode set and the control rule are now fixed
  in code (§9) *before* any result is inspected.
- **Basin scope:** Tapi first. Godavari later as a **replication basin**, not a
  sample-size booster — its value is testing whether findings transfer, and the two
  should never be pooled into one bias matrix.
- **Stage 2 rule (when it starts):** validate with whole held-out *years*, never a
  random split — rainfall autocorrelation makes random splits leak. Baselines
  (monthly ratio scaling, quantile mapping) must be beaten before ML counts.

## 7. Honest assessment of the project

Novelty is **moderate at best** as framed — SPP validation against IMD is a
saturated genre in Indian hydrometeorology, and ML bias correction over Indian
basins is well established. Where genuine contribution is available:

- terrain-conditioned bias in the Satpura–Tapi transition (a real known SPP weak
  spot), done with actual elevation rather than proxies;
- a rigorously defined, significance-tested episode amplification metric — the
  episode set is now rule-derived and pre-registered in code (§9), which is the
  part the old DPBA lacked;
- an operational endpoint — corrected product feeding a flood model for Surat —
  which would give the work a "so what".

**Standing caveat that must appear in any write-up:** IMD gridded data is itself
interpolated from a sparse gauge network. Over hill terrain it is not truth, and
part of any measured "satellite bias" is IMD's own interpolation error. Stage 2
corrections learn *IMD*, not reality.

## 8. Working style that has been effective

- Ask before each task; work on the user's actual files rather than pasting code.
- Compile/validate every script before handing it over; several bugs were caught
  this way (a missing `import re`, an empty file, a 0-byte save).
- When a check fails, first ask whether the *check* is wrong — two CHIRPS
  "failures" were over-strict verification, not bad data.
- The user is a student learning the domain: explain *why*, flag when a stated
  rationale is wrong (e.g. "dry days will mess up the calculations" — they won't),
  and never let a plausible-sounding but incorrect justification into the methods.

## 9. Episode definition (settled 2026-08-12)

Hand-picked flood windows were abandoned. Episodes are derived by
`src/stage1/define_episodes.py`, cached to `data/processed/rainfall_episodes.json`,
and read through `basins.load_episodes()` — which raises if the file is absent, so
no analysis can run on an assumed event set.

**Selection rule (fixed):** score every 3-day window in 2015–2023 by basin-mean IMD
rainfall summed over the window; take the top 10 greedily with ≥ 7 days between
selected window starts; windows may not straddle a year boundary. No manual
additions or removals.

**Naming:** these are extreme **rainfall** episodes, not floods. A flood is a
river-stage phenomenon and Ukai's regulation partly decouples basin rainfall from
stage at Surat; rainfall is what the satellite products actually observe, so it is
what this study can honestly claim to measure bias in.

**Control days (fixed before any result was inspected):** same year as the episode,
inside JJAS, basin mean ≥ 1.0 mm, and not within 3 days of any episode. Yields 702
control days (49–95 per year) against 30 episode days.
